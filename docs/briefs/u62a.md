## Part A — codex entries unlock by `unlockWhen`

Today an entry unlocks **only** through an `unlockCodex` effect (`src/engine/effects.ts`). `unlockWhen` is documentation
(`src/ui/panels/codexModel.ts` header says so). Only 11 of 90 entries have an `unlockCodex` effect pointing at them, so **79
can never unlock in play**, including most of Codex I. STORY §14 and DESIGN mean the conditions to be live.

Do:
- At the end of every `step`, evaluate the `unlockWhen` of each still-locked codex entry with the existing evaluator
  (`src/engine/conditions.ts` `evaluate(cond, state, profile, content)`). Unlock those that hold, through the same path as
  the effect: `profileDraft().codexUnlocked`, plus the `codexUnlocked` event, so the UI toast, Resonance and achievements work.
- An entry without `unlockWhen` stays effect-only.
- **Keep it cheap:** `step` runs millions of times in sims. Index entries by the atoms they read: echo, location, region,
  killed, quest, companion, corruption, flag, item. Re-evaluate only entries whose atoms an event this step could have changed
  (an Echo granted, a move, a kill, a quest change, a companion change, a flag or Corruption change). Measure `npm run
  sim:batch` time before and after and report it: no more than 5% slower.
- Determinism and replay are unchanged. The pass has no RNG.
- **Check:**
  - a test that each of the 90 entries unlocks when its condition is made true on a built state;
  - the real-pack sims now unlock codex entries (report how many per bot over a short batch);
  - the existing `unlockCodex` effects still work.

Update the `codexModel.ts` header.

## Part B — text out of the main JS bundle

Production JS is **577.7 kB gzip of 600** (D-115, D-129); U62 will add the 20 key scenes, the ending slides and epilogues, all
text. D-115 says: split or lazy-load content, don't raise the budget.

Do:
- **Measure first.** Report which content is biggest by gzip: dialogue node text, codex bodies, location descriptions and
  variants, ending text, item and creature descriptions, Echo lines.
- Move the **long prose** into lazily loaded JSON chunks, loaded on first use and cached. Candidates: codex bodies, dialogue
  node text, ending slides and epilogues. Engine-relevant data stays in the bundle: ids, conditions, effects, numbers, names.
  The engine and the sims must not depend on the chunks: they never read prose, or read it through a provider that the sims
  fill synchronously from source.
- **UI:**
  - A dialogue or codex view waits for its chunk with a tiny, quiet loading state. Preload the next likely chunk: the
    current region's dialogue, the codex when the panel opens.
  - Offline-friendly: the chunks are hashed static files beside the bundle.
  - The e2e build uses the same split.
- **Budget:** report production JS before and after. Aim for **≤ 520 kB**, leaving U62 and later units room. The chunks are
  outside the JS budget, like the art, but report their total.
- **Validation is unchanged.** `npm run validate` still checks word limits and references over the full text.
